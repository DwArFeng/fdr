# Resetter - 重置器

## 说明

重置器用于在运行过程中重置与本地缓存相关的功能状态。
当数据、配置或运行资源发生变化后，相关更新可能无法继续传递到已经构建好的本地缓存中，本地缓存中仍然保留旧数据、旧配置或旧会话。
此时需要通过重置器清理或重建这些运行时状态，使系统在不重启整个进程的情况下重新加载相关资源。

重置器主要面向以下场景：

- 抓取器配置变更后，关闭旧会话并清空抓取器本地缓存。
- 记录链路配置变更后，清空记录本地缓存和记录记忆。
- 映射器配置变更后，清空映射本地缓存。
- 集群内某个节点完成变更后，将重置动作广播到其它节点。

重置器可以分为两类：

| 类型    | 说明                                  |
|-------|-------------------------------------|
| 被动重置器 | 依赖定时、CRON 等被动条件触发，适合周期性刷新本地缓存。      |
| 主动重置器 | 依赖外部调用触发，通常配合集群广播，让多个节点在同一类事件后同时重置。 |

主动重置器的典型实现是 `DubboResetter`。
调用方通常通过 Dubbo 的 `broadcast2` 等广播方式调用远程重置接口，让集群内所有节点上的重置器同时执行重置动作。

## 接口

重置器 `Resetter` 是一个接口，主要方法如下：

- `void init(Context context)`：初始化重置器，保存重置器运行时上下文。
- `void start() throws HandlerException`：启动重置器， 注册触发条件或暴露远程入口。
- `void stop() throws HandlerException`：停止重置器，取消触发条件或释放远程入口。

具体方法的说明请参阅接口的 JavaDoc。

### Context

`Context` 为重置器提供运行时上下文，主要方法如下：

| 方法签名                 | 说明      |
|----------------------|---------|
| `void resetRecord()` | 重置记录功能。 |
| `void resetMap()`    | 重置映射功能。 |
| `void resetFetch()`  | 重置抓取功能。 |

重置器实现不直接操作各类本地缓存，而是通过 `Context` 调用统一的重置入口。
统一入口由 `ResetProcessor` 负责执行，可以保证停止处理器、清空缓存、恢复处理器和推送消息等动作保持一致。

### ResetHandler

`ResetHandler` 是重置处理器，负责启动、停止重置服务，并提供手动重置记录功能、映射功能和抓取功能的入口。

当重置服务启动时，`ResetHandler` 会获取当前生效的全部重置器，并依次调用每个重置器的 `start()` 方法。
当重置服务停止时，`ResetHandler` 会依次调用每个重置器的 `stop()` 方法。
单个重置器启动或停止失败时，异常会被记录到日志中，不会阻止其它重置器继续启动或停止。

### ResetQosService

`ResetQosService` 是重置功能的运维服务入口。
Telqos 的 `reset` 命令通过该服务查看重置器、查看启动状态、启动服务、停止服务，以及手动执行记录、映射、抓取功能的重置操作。

## 重置器的生命周期

### 初始化

程序启动并完成 Spring Bean 加载后，`ResetterHandler` 会收集当前生效的全部 `Resetter` Bean，
并为每个重置器调用 `init(Context)` 方法。

重置器应在初始化阶段保存 `Context`，后续定时任务、远程入口或其它触发逻辑需要通过该上下文执行实际的重置动作。

### 启动

重置服务启动时，`ResetHandler` 会调用各重置器的 `start()` 方法。

不同重置器在启动阶段执行的动作不同：

- 定时类重置器会向 `ThreadPoolTaskScheduler` 注册计划任务。
- 远程类重置器会暴露远程服务入口。
- 空重置器不会注册任何触发条件。

程序启动后是否自动启动重置服务，由 `com.dwarfeng.fdr.launcher.start_reset_delay` 控制。
该参数等于 `0` 时，程序启动后立即启动重置服务；该参数大于 `0` 时，程序启动后延迟指定毫秒数启动重置服务；
该参数小于 `0` 时，程序不会主动启动重置服务，需要通过 Telqos 手动启动。

### 执行重置

重置动作由 `ResetProcessor` 统一执行。`ResetProcessor` 内部使用锁保护重置过程，
避免多个重置请求同时修改同一批本地缓存和处理器状态。

重置完成后，`ResetProcessor` 会尝试通过推送处理器发送对应的重置消息。
如果推送失败，重置本身不会回滚，日志中会记录本次重置消息未能推送的异常信息。

### 停止

重置服务停止时，`ResetHandler` 会调用各重置器的 `stop()` 方法。

定时类重置器会取消已经注册的计划任务。远程类重置器会取消暴露的远程服务。空重置器不会释放额外资源。

## 工作机制

### 记录功能重置

记录功能重置用于刷新记录链路相关的本地状态。实际执行顺序如下：

1. 读取当前抓取处理器和记录处理器的启动状态。
2. 停止抓取处理器，避免重置过程中继续抓取新数据。
3. 停止记录处理器。
4. 清空记录本地缓存处理器。
5. 清空记录记忆处理器。
6. 如果记录处理器在重置前处于启动状态，则重新启动记录处理器。
7. 如果抓取处理器在重置前处于启动状态，则重新启动抓取处理器。
8. 推送记录功能重置消息。

记录功能重置会影响记录链路正在处理的数据，在逻辑侧消费者或记录侧消费者积压较多时可能消耗较长时间。

### 映射功能重置

映射功能重置用于刷新映射器相关的本地状态。实际执行顺序如下：

1. 清空映射本地缓存处理器。
2. 推送映射功能重置消息。

映射功能重置不会停止抓取处理器和记录处理器，但后续映射请求会重新从配置和上下文中构建映射器。

### 抓取功能重置

抓取功能重置用于刷新抓取器、抓取会话和抓取器本地缓存。实际执行顺序如下：

1. 读取当前抓取处理器的启动状态。
2. 停止抓取处理器。
3. 关闭并清除抓取器会话保持处理器。
4. 清空抓取器本地缓存处理器。
5. 如果抓取处理器在重置前处于启动状态，则重新启动抓取处理器。
6. 推送抓取功能重置消息。

抓取功能重置适合用于抓取器配置、连接资源、监听会话发生变化的场景。

### 定时重置

定时重置属于被动重置。系统内置的定时类重置器会在触发时重置记录功能和映射功能。

| 类型            | 说明                                 |
|---------------|------------------------------------|
| `fixed_delay` | 上一次任务执行完成后，等待指定间隔再执行下一次任务。         |
| `fixed_rate`  | 按固定频率调度任务，不以任务完成后的等待时间作为下一次调度依据。   |
| `cron`        | 按 CRON 表达式调度任务，适合每天固定时间或复杂周期的重置策略。 |

### 远程重置

远程重置属于主动重置。系统内置的 `DubboResetter` 会在启动时暴露 Dubbo 服务，外部调用者可以调用远程接口触发记录功能或映射功能重置。

在集群部署时，调用者通常使用广播调用方式，让所有节点都收到相同的重置请求。
这种方式适合配置变更、点位变更、映射变更等需要同步刷新全节点本地缓存的场景。

### 永不重置

永不重置用于明确表示“不通过重置器自动触发重置”。
当项目只希望通过 Telqos 手动执行重置，或者暂时不希望启用任何定时或远程触发入口时，可以使用该实现作为占位。

## 运维与配置

重置器相关配置主要分布在以下文件中：

| 文件                             | 说明                 |
|--------------------------------|--------------------|
| `conf/fdr/reset.properties`    | 重置器参数配置。           |
| `opt/opt-resetter.xml`         | 决定加载哪些重置器实现。       |
| `conf/fdr/launcher.properties` | 决定程序启动后是否自动启动重置服务。 |

`opt/opt-resetter.xml` 中可以通过 Spring 的 `include-filter`，选择需要加载的重置器。
如果没有加载任何重置器，重置服务启动后不会注册定时任务或远程入口，但仍然可以通过 Telqos 手动执行重置命令。

常用 Telqos 命令如下：

| 命令                     | 说明          |
|------------------------|-------------|
| `reset -l`             | 查看当前生效的重置器。 |
| `reset -status`        | 查看重置服务启动状态。 |
| `reset -start`         | 启动重置服务。     |
| `reset -stop`          | 停止重置服务。     |
| `reset --reset-record` | 手动重置记录功能。   |
| `reset --reset-map`    | 手动重置映射功能。   |
| `reset --reset-fetch`  | 手动重置抓取功能。   |
